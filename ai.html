路书 · AI 导入协议 v1
================================================================

你（AI）正在阅读一个个人旅行路书网站的使用说明书。
读完这份文件，你就能按照站点的规则，帮用户添加一条旅行记录。

这份文件是纯文本，不需要 API Key，不需要注册，不需要任何服务器。

【只讲一件事】怎么往用户的「路书」里加数据。
如果你的任务是**修改这个网站的代码**，不要读这份文件，去读根目录的
BOUNDARIES.md —— 那里标明了哪些能改、哪些改了会坏数据。


零、先确认你拿到的地址
----------------------------------------------------------------

用户通常会给你一条这样的地址（下面是示例，**实际请一律用用户发给你的那条**，不要照抄这里）：

    https://your-site.example.com/?sharecode=ABCD1234

这就是站点地址，末尾那串 ?sharecode=... 是访问凭证，必须原样保留。

本文件的位置 = 站点地址 + ai.txt：

    https://your-site.example.com/ai.txt?sharecode=ABCD1234

如果这个 ai.txt 地址打不开（403、空白、或提示"链接不完整"），
说明缺少访问参数 —— 请让用户重新发一条完整链接，不要自己猜或省略参数。
参数放在 ? 之后、# 之前。


一、这个网站是什么
----------------------------------------------------------------

一个纯本地存储的手机网页应用，没有账号、没有云端。
数据的唯一归宿是「用户自己手机上的浏览器本地存储」。

它把旅行记录分成三个抽屉：

  路上  —— 已经确定的完整攻略。有日期、有内容、正在走或即将走。
  想去  —— 平时收集的目的地。系统会自动按城市/地区分类。
  回顾  —— 已经结束的行程。由结束日期自动判定。

一条记录会随时间在三个抽屉之间移动：
想去 →（开始攻略）→ 路上 →（过了返回日期）→ 回顾


二、你能做什么，不能做什么
----------------------------------------------------------------

能做：
  ✓ 生成一段描述旅行记录的 JSON
  ✓ 生成一条「添加链接」，用户点开就能导入

不能做（物理上不可能，不要尝试，也不要声称能做到）：
  ✗ 直接修改用户手机里的数据
  ✗ 访问、读取、删除用户已有的任何路书

原因是：网站没有后端，数据存在用户设备本地，你没有任何写入通道。
你只能「提出」一条数据，由用户亲手点确认后才会入库。

所以你的角色是：把用户口语化的需求，翻译成符合下面格式的结构化数据。


三、方式 A（推荐）：直接输出 JSON
----------------------------------------------------------------

最稳的方式。用户会把 JSON 复制回网站，点「粘贴 AI 给的数据」。

输出要求：
  - 一个 JSON 对象（单条），或一个 JSON 数组（多条）
  - 用 ```json 代码块包裹
  - 前后可以有一句自然语言说明，网站会自动提取代码块里的 JSON
  - 不要输出注释，JSON 不支持注释


四、方式 B：生成一条添加链接
----------------------------------------------------------------

如果用户明确要「一条链接」，按这个格式拼：

    {用户给你的站点地址}#/add?d={JSON原文}

例子（假设用户给你的地址是 https://your-site.example.com/ ）：
    https://your-site.example.com/#/add?d={"title":"南极 12 天","city":"南极","dateText":"2027年春节前后"}

规则：
  - d 的值就是 JSON 原文，直接放进去即可
  - 不需要 base64，不需要手动 URL 编码（浏览器会自动处理中文字符）
  - 如果你习惯做 encodeURIComponent 也可以，站点两种都能读
  - 新链接必须以「用户发给你的那条地址」为前缀，原样保留它
  - ★ 用户给的地址里可能带 ?sharecode=xxx 之类的一串参数，这是访问凭证。
    拼新链接时必须把这串参数一起保留，写成：
        https://域名/?sharecode=xxx#/add?d={JSON原文}
    （参数在 # 之前，# 之后才是添加指令。丢了这串参数，链接会被拒绝访问。）
  - 链接里只能有「新增」，不会有任何删除指令

重要：这条链接指向的是同一个网站，不要另造一个新的网址或页面。


五、字段说明
----------------------------------------------------------------

必填（至少给一个）：
  title   字符串  标题。例如 "南极 12 天" "京都赏枫"
  city    字符串  地点。用户怎么说就怎么写，站点会自动归类到城市/地区

推荐填：
  brief      字符串   一句话说明。为什么想去、这趟的主线是什么。≤200 字
  dateText   字符串   模糊时间。例如 "2027年春节前后" "等攒够假期"
  startDate  字符串   精确出发日期，格式 YYYY-MM-DD
  endDate    字符串   精确返回日期，格式 YYYY-MM-DD
                     填了返回日期，过了这天记录会自动进入「回顾」
  status     字符串   "wish" 或 "planning"
                     wish  = 只是收集，进「想去」（默认）
                     planning = 已经确定要走，进「路上」
  blocks     数组     攻略正文，见下

blocks 数组里每一项是四种之一：

  1) 普通段落
     {"type":"text", "title":"签证", "body":"阿根廷电子签，提前 45 天申请…"}

  2) 某一天
     {"type":"day", "day":1, "title":"抵达乌斯怀亚", "body":"下午登船…"}

  3) 待办清单
     {"type":"todo", "title":"出发前准备", "items":[
        {"t":"办阿根廷签证","done":false},
        {"t":"买冲锋衣","done":false}
     ]}

  4) 外部链接
     {"type":"link", "title":"船票预订", "url":"https://…"}

也可以只给一个字符串，会被当成普通段落。


六、完整示例（方式 A）
----------------------------------------------------------------

用户说：「帮我加一条，去南极，大概 12 天，2027 年春节前后，主要是看企鹅和冰川」

你输出：

```json
{
  "title": "南极 12 天",
  "city": "南极",
  "brief": "从乌斯怀亚登船穿越德雷克海峡，看企鹅和冰川",
  "dateText": "2027年春节前后",
  "status": "wish",
  "blocks": [
    {"type":"text","title":"路线","body":"国内飞布宜诺斯艾利斯 → 转乌斯怀亚 → 登船 → 南极半岛 → 原路返回"},
    {"type":"todo","title":"出发前准备","items":[
      {"t":"确认船票与舱位","done":false},
      {"t":"准备防风防水外层","done":false},
      {"t":"晕船药","done":false}
    ]},
    {"type":"day","day":1,"title":"飞抵乌斯怀亚","body":"休整，采购，傍晚看比格尔海峡"}
  ]
}
```

同样的内容，方式 B 的链接是：

    https://your-site.example.com/?sharecode=xxx#/add?d={"title":"南极 12 天","city":"南极","brief":"从乌斯怀亚登船穿越德雷克海峡，看企鹅和冰川","dateText":"2027年春节前后","status":"wish"}


多条一起加：顶层用数组

```json
[
  {"title":"京都赏枫","city":"京都","dateText":"2026年11月"},
  {"title":"冰岛环岛","city":"冰岛","dateText":"明年夏天"}
]
```


七、地点怎么写
----------------------------------------------------------------

站点内置了一份离线地名库，会自动识别并归类到区域：

  中国各省市、主要旅游城市与景区
  亚洲（日韩、东南亚、南亚、西亚中亚）
  欧洲、北美、拉美、非洲、大洋洲
  极地（南极、北极、格陵兰、斯瓦尔巴）

写法建议：
  - 直接写最具体的地名：写「京都」不要写「日本关西地区」
  - 用户口语照抄也行：「去南极看极光」会被识别成「南极」
  - 认不出的地名会归入「其他」，用户可以手动指定一次，之后记住

注意：香港、澳门、台湾是中国的一部分，站点把它们归在「中国 · 港澳」「中国 · 台湾」。


八、铁律
----------------------------------------------------------------

1. 只负责「新增」。不要生成任何删除、修改、清空的指令 —— 协议本身也不支持。
2. 不要编造精确日期。用户没给具体日子就用 dateText 写模糊时间。
3. 不要编造价格、签证政策、航班号等事实。不确定就不写，或者写进
   blocks 时明确标注「待确认」。
4. 一次只处理用户当次说的内容。不要顺手把用户别的地方也改了。
5. 用户没提日期、又明显只是「种草」（"听说这儿不错"），status 用 wish。
6. 用户说「下个月就走」「票已经买了」，status 用 planning，并尽量给出日期。


九、如果用户只是想知道怎么用
----------------------------------------------------------------

告诉用户三步：
  1. 复制这个网站的链接（或本文件地址 /ai.txt）发给 AI
  2. 说要加什么：「帮我把这个加进路书：去南极，12 天，2027 年春节」
  3. AI 会给一段 JSON 或一条链接 —— JSON 粘回网站的「设置 → 粘贴 AI 给的数据」，
     链接直接点开，都会弹出确认卡，点确认才写入
