# 在路书 · 旅行路书

一个纯本地存储的旅行计划本。三个抽屉，一条时间轴，一份给 AI 看的说明书。

**没有账号，没有后端，数据不出浏览器。** 打开就是你的，关掉还在，换个设备就没有了——这是刻意的取舍。

---

## 三个抽屉怎么分

```
想去  ──开始攻略──▶  路上  ──过了返回日期──▶  回顾
```

| | 装什么 | 怎么进来 | 怎么出去 |
|---|---|---|---|
| **路上** | 已经确定的完整攻略 | 新建时填了精确出发日期；或从「想去」点「开始攻略」 | 过了返回日期自动进「回顾」；也可手动提前结束 |
| **想去** | 平时随手收集的目的地 | 新建时不填日期；AI 导入时说 `status: wish` | 不删除，升级后沉到列表底部灰显，可手动移出 |
| **回顾** | 已经结束的行程 | 返回日期过了自动搬进来 | 可「拉回路上」应对改签延期 |

三条判定规则（`js/store.js` 的 `tripState`）：

1. **精确日期**：`今天 > 结束日` → 回顾；`在区间内` → 进行中；`还没到` → 待出发。只填出发日不填返回日，则会一直算进行中，直到手动结束。
2. **模糊时间**（"2027 年春节前后"）：**不自动归档**。日子过了只会在详情页软提示"结束了吗"，你点头它才走 —— 因为机器不该替你决定一趟旅行算不算结束。
3. **手动覆盖优先**：任何自动判定都能被"提前结束 / 拉回路上"推翻。

## 本地跑起来

需要一个 HTTP 服务器（不能直接双击 `index.html`，ES Module 和 IndexedDB 都要 http 协议）：

```bash
npm install        # 只为开发用（打包、测试）；跑站点本身不需要依赖
npm start          # 等价于 node server.js，默认 8080 端口
```

打开 `http://127.0.0.1:8080/`。

开发时想用别的端口：

```bash
PORT=8765 npm start
```

用手机看：手机和电脑连同一个 Wi-Fi，把地址换成电脑的局域网 IP。
想看真机效果，Chrome DevTools 里切到 iPhone 设备模式即可。

## AI 怎么往里加东西

### 原理（为什么只能这样）

数据存在**你手机浏览器的 localStorage**，任何外部服务都写不进去。所以 AI 不可能"直接更新"你的路书，它只能：

1. 读你站点上的 `/ai.txt`（一份 4000 字的纯文本说明书）
2. 按规范吐出一段 JSON，或一条指向你站点的 `#/add?d=...` 链接
3. 你（或你朋友）点开 → 弹确认卡 → 点确认 → 才写进本地

**全程没有服务器参与，数据一直在各自手机里。** 这条链接谁点开，数据就进谁的手机 —— 它的准确含义是"分发"，不是"同步"。

### 怎么用

把这段话发给元宝 / 千问 / Kimi / 任何 AI（网站「设置 → 怎么让 AI 帮你加」里可以直接复制）：

> 帮我往「路书」里加一条旅行记录。网站是：`https://你的域名/`
> 能打开的话先读 `/ai.txt` 了解格式……
> 我要加的：去南极，12 天，2027 年春节前后

AI 会回你一段 JSON 或一条链接：
- **JSON** → 复制 → 设置页「粘贴 AI 给的数据」
- **链接** → 直接点开，弹确认卡

### 安全边界

- 导入通道**只支持新增**，协议里没有任何删除/修改指令
- 所有导入都要你亲手点确认，原始数据可展开查看
- AI 只能"提议"，碰不到你已有的任何一条记录

### 改了协议内容之后

`ai.html` 是由 `ai.txt` 生成的，改完 txt 记得重跑：

```bash
node scripts/sync-ai.mjs
```

（两份都留是因为：`ai.txt` 省 token 但部分服务器不给 charset 可能乱码；`ai.html` 带 `meta charset` 永远不会乱码。）

## 数据在哪，怎么不丢

| 内容 | 位置 |
|---|---|
| 路书正文、城市、日期 | `localStorage` key = `lushu.v1` |
| 封面图片（压缩后的 webp） | `IndexedDB` 数据库 `lushu-db` |
| 上一次的旧版本 | `localStorage` key = `lushu.v1.bak` |

**换手机、清缓存、换浏览器，数据都会没。** 所以设置页有「导出完整备份」——它会把图片一起转成 base64 打包进一个 JSON 文件。换设备时用「从备份文件恢复」，选合并或覆盖。

图片导入时会压缩到长边 1600px、webp 质量 0.8，单张约 150–300KB。localStorage 只有 5MB，所以正文有大小限制，图片单独走 IndexedDB。

## 城市自动分类

`js/cities.js` 内置约 350 条地名（中国省市 + 世界热门目的地 + 极地），运行时展开成名称与别名索引。

匹配顺序（`js/city.js`）：

1. 用户手动指定过的说辞（存在 `aliases` 里，会自我学习）
2. 剥掉"我想去 / 明年 / 打算去"这类前缀
3. 整串精确命中
4. 包含命中：**先找正式地名，再找别名** —— 否则"我想去冰岛看极光"会被"极光"抢走判成芬兰
5. 都没中 → 归「其他」，编辑页可以手动指定一次，下次自动认出

全程离线，不联网、不调大模型。

## 已知边界

- 状态流转在**打开 App 时**跑一次，纯前端没法后台定时。所以"过期没自动归档"的话，重开一次就好。
- 一条攻略只能有一个城市/区域（不支持多城连线）。多城路线建议写在正文里。
- 没有云端、没有账号、没有协同。发给朋友的链接是"给他一条数据"，不是"共享你的库"。

## 构建

改完 `js/` 或 `css/` 之后**必须重新打包**，否则浏览器加载的还是旧的 `bundle.js`：

```bash
npm run build
```

然后把 `index.html` 里 `bundle.js?v=` 和 `app.css?v=` 的版本号往后推一位。这个项目没有文件指纹，靠版本号破缓存。

## 改动边界

`BOUNDARIES.md` 里分了三档：骨架（数据模型、路由、存储键名、状态机）、需要同步的位置、可以随意发挥的表现层。动手前先看一眼，尤其是那几个 localStorage 键名。
